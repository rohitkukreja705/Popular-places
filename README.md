# Bhopal Food Map

A Flutter app showing 221 Bhopal food places (kebab trail, sweets, street
stalls, cafes, etc.) on a free OpenStreetMap-based map — no Google Maps API
key, no billing account.

## How it's built

- **Map**: `flutter_map` (OSM raster tiles) + `latlong2`
- **Data**: `assets/bhopal_food_places.json` — 221 places / 25 categories,
  each with name, area, "known for", category, and lat/lng
- **No local Android folder is committed.** `android/` is regenerated by
  `flutter create` inside GitHub Actions on every build (see
  `.github/workflows/build.yml`), so nothing here depends on a local Flutter
  install to get a working build.

## Repo layout

```
pubspec.yaml
lib/main.dart                 — the whole app (map, search, category filter,
                                 marker bottom sheet, "open in Google Maps")
assets/bhopal_food_places.json
.github/workflows/build.yml   — builds a release APK, uploads it as a
                                 workflow artifact
push_to_github.py             — pushes these files to a new/existing repo,
                                 file-by-file via the Contents API
```

## Push this to GitHub

```
export CONTENTS_TOKEN=github_pat_xxx      # Contents: Read & write
export WORKFLOWS_TOKEN=github_pat_yyy     # + Workflows: Read & write
                                           # (can be the same token if it has both)
python3 push_to_github.py --owner YOUR_USERNAME --repo bhopal-food-map --branch main
```

Then check the **Actions** tab on GitHub — the build should start
automatically on the first push to `main`, and the finished APK shows up
under that run's **Artifacts**.

## Known follow-ups

- **Debug-keystore consistency**: because `android/` is freshly generated
  every CI run, each build's APK is signed with a fresh ephemeral debug key —
  installing a new build over an old one on the same phone will fail until
  you uninstall the old one first (same issue hit on Zentra-App; fix there
  was committing a fixed `debug.keystore` and pinning
  `signingConfigs.debug` to it). Ask to have this applied once the first
  build succeeds and the generated `build.gradle` can be inspected directly.
- **Tile provider**: currently points at the shared `tile.openstreetmap.org`
  servers, which is fine for development but OSM's usage policy asks
  heavier-traffic or public apps to move to a dedicated free tile provider
  (Stadia Maps, MapTiler, or a self-hosted OpenMapTiles instance) instead.
- **Marker clustering**: at 221 markers, city-wide zoom is a little busy.
  `flutter_map_marker_cluster` would group nearby pins — held off on v1 to
  keep the dependency list minimal until the base build is confirmed working.
- **App icon / name polish**: currently uses Flutter's default icon.
